# ADR 001: PostgreSQL, Sequelize, and integer money

**Status:** Accepted

**Date:** 2026-09-21

## Context

The project teaches concurrency using Node.js, TypeScript, PostgreSQL, and Sequelize. It needs exact money arithmetic and database constraints that remain effective outside HTTP validation. A small codebase should make the SQL behavior easy to inspect.

## Decision

Use Sequelize 6 for typed models and transaction management, with PostgreSQL 17 as the actual development and test database. Keep explicit, versioned DDL in `src/db/schema.ts` rather than deriving the schema through destructive model synchronization. Serialize migration runners using a transaction-scoped advisory lock.

Represent money as integer minor units in one implicit currency. Use PostgreSQL `INTEGER` with a range of 0–2,147,483,647 for balances and 1–2,147,483,647 for transfer amounts. The API validates this range and checks receiver overflow before updating. Use UUID primary keys generated by Node.js.

## Options considered

| Option | Benefit | Cost |
| --- | --- | --- |
| INTEGER minor units — chosen | Exact arithmetic, ordinary JSON numbers, simple checks | Explicit upper bound |
| BIGINT minor units | Larger balances | Driver strings or BigInt serialization/conversion policy |
| NUMERIC amounts | Flexible decimal precision | Decimal library and consistent scale required |
| Floating-point amounts | Familiar number handling | Rounding makes it inappropriate for money |

## Consequences

The demo has a deliberate balance ceiling and no multi-currency support. Increasing the ceiling requires a migration and API representation decision. Database checks enforce non-negative balances, positive amounts, distinct account IDs, valid status, and non-empty keys; foreign keys enforce account existence. These constraints are defense in depth, not a substitute for locking or authorization.

Opening balances are a learning convenience. A real financial system would need authenticated ownership, funding controls, ledger entries, reconciliation, audit retention, and currency rules.
